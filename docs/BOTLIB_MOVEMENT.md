# Movement state boundary

`craftq3-botlib` contains owned movement input/result records and a bounded `BotMovement` state provider. It implements allocation, free, reset, initialization, player-input flags, timed reach avoidance and avoid-spot storage. Physical travel execution remains a separate service.

The public 32-bit records are written explicitly in little-endian order:

| Record | Bytes | Offsets |
|---|---:|---|
| `bot_initmove_t` / `MovementInit` | 68 | origin 0, velocity 12, view offset 24, entity 36, client 40, think time 44, presence 48, view angles 52, input flags 64 |
| `bot_moveresult_t` / `MovementResult` | 52 | failure 0, type 4, blocked 8, blocking entity 12, travel type 16, flags 20, weapon 24, direction 28, ideal view 40 |
| `bot_avoidspot_t` | 20 | origin 0, radius 12, type 16 |

Record reads and writes preserve the caller's buffer position and byte order. Coordinates are finite and quantized to 32-bit floats; think time is finite and bounded to 0–3600 seconds. Flags, result words and entity/client identifiers remain opaque integers. Input records are immutable.

`BotMovement` allocates the lowest free handle from 1–64. Free and reset discard initialization and avoid spots. Initialization replaces the supplied input while retaining avoid spots. The provider stores at most 32 spots and ignores additions past that limit. Clear removes spots while retaining initialization. Immutable snapshots are for diagnostics and future movement integration, not a representation of an upstream private structure. Invalid handles produce diagnostics and empty/no-op results; use after close fails.

`BotlibHost` bridges calls 548, 551–552, 555–557 and 574 to this provider. Clear-avoid-spot requests do not dereference their unused input vector. Call 553 shares the verified reachable-area provider used by item selection (535–536). Call 554 exposes the [movement view-target helper](BOTLIB_MOVEMENT_VIEW.md). Directional movement and move-to-goal integration remain incomplete.

Initialization replaces only player-supplied flag bits 626 (`ONGROUND`, `WATERJUMP`, `TELEPORTED`, `GRAPPLEPULL`, `WALK`), retaining other prior runtime bits. Snapshots distinguish this effective flag word from the original input word. The single timed reach slot records a link, expiry and attempt count. Repeating the same link refreshes expiry and increments attempts only while its old expiry is strictly later than now; otherwise attempts restart at one. A different link can replace the slot only when its expiry is strictly earlier than now. Thus equality has intentionally different consequences for refresh and replacement. A new attempt at time zero does not replace the initially zero-expiry empty slot.

Reset-all clears all three reach-slot fields. Reset-last clears a positive expiry and refunds one attempt down to zero, preserving the link; repeated resets do not keep decrementing. Both retain input and avoid spots. Finite negative durations are preserved as native arithmetic permits; nonfinite times, negative current time and attempt-count overflow fail before mutation. Eight authored movement-state tests include these boundaries and immutable before/after snapshots. `scripts/AuditBotMovementState.java` compares 20,000 mixed attempt, clock, reset and initialization operations: all native reach, expiry float bits, tries and effective flags match. Its authored C observer links unchanged native movement code; `BotMoveStateMetadata.h` is an attributed data-layout declaration for observation only, containing no engine routines.

java -cp craftq3-core/build/classes/java/main:craftq3-botlib/build/classes/java/main scripts/AuditBotMovementState.java .tools/move-state-oracle/probe

## Static presence traces and measured movement predicates

`AasPresenceTrace(AasMap)` and `AasNavigation.presenceTrace(start,end,presenceMask)` trace through the AAS partition that already encodes expanded presence hulls. They return start-solid, fraction, backed-off end position, last traversable area, blocked area and oriented plane number. A solid leaf or area with no matching presence bit blocks. The traversal is iterative, limited to one million visits by default, and rejects coordinates outside the bounded float range. The returned entity is zero for static geometry; `AasMovementWorld` adds dynamic clipping inside permitted leaf segments.

The observed native collision result applies a 0.125-unit split offset, replaces a split fraction outside [0,1] with 0.001 or 0.999, preserving tiny valid fractions, then backs the final position another 0.125 units along the normalized full requested ray. The returned fraction refers to the point before that final backoff, so reconstructing the final position from the fraction would differ. Seven authored tests cover these values, presence masks, starting in blocked areas, oriented planes, zero-distance boundary starts and query budgets. Controlled native comparison passed 3,005 single-partition rays and 3,500 multi-partition rays: all discrete fields matched and the largest float difference was approximately 0.00000107. The expanded audit compares 300,000 rays across all 30 original AAS maps with unchanged native sampling code compiled with float contraction disabled. Every discrete field matched, with maximum float difference 0.000015 units. ARM fused arithmetic in the default native build caused eight rare boundary/endpoint differences; Java deliberately uses reproducible non-fused float operations. A further 404-ray margin corpus covers both traversal directions and 50 adjacent float values on each side of the exact 0.125 margin, including oblique rays: all discrete fields match and numeric differences remain below 0.000001. At the exact margin, a zero-length permitted-leaf visit can precede a blocked leaf; the native result is start-solid with the original position, the visited last area, and the raw partition plane rather than the ordinary oriented hit plane. This distinction also makes the native ten-unit ground predicate false at the original q3ctf1 `(1262,-69.9,128.125)` and q3dm1 `(816.9,210,32.125)` boundaries. The 300,000-map-ray regression was rerun after this correction with the same result. Dynamic composition is audited separately below.

Additional unchanged-code probes established that `AAS_OnGround` traces the presence hull down ten units and accepts a non-start-solid hit with fraction below one and plane normal Z at least `phys_maxsteepness` (default 0.7). `AAS_DropToFloor` instead performs one BSP box trace down 100 units, with mask `CONTENTS_SOLID` and pass entity zero; it rejects only a start-solid result, otherwise using the trace endpoint even when no floor was hit. These observations guide the ongoing movement and item-placement adapters; they do not imply completed prediction physics.

## Bounded movement prediction

`AasMovementPredictor` exposes a pure Java prediction service with an injected `World` for presence traces, planes, area/presence lookup and contents. Immutable requests bound command and prediction frames to 4096 and require a finite frame duration in (0,1]. Settings read the published `phys_*` variables. The collision loop permits twenty main movement traces in a frame. A twenty-first clear trace fails; a twenty-first blocked contact first processes its step probe or requested damaging-impact event. Such a damaging stop can succeed, while an ordinary or accepted-step result at that limit fails. A controlled native callback and regression test verify this ordering. Nineteen blocked traces followed by a twentieth clear trace can succeed. Successful predictions supply an explicit trace: ordinary completion and fluid-entry stops return a cleared 36-byte record, while ground, damaging-impact and gap stops retain the main movement trace. A separate unchanged-code probe initializes all 84 output bytes to a nonzero sentinel and verifies the cleared trace, including zero-frame completion. This corrects the earlier inference from probes whose outputs began at zero.

The verified domain covers dry and swimming open air, flat upward-facing floors and positive inclines, ceilings at arbitrary inclinations, vertical walls at arbitrary horizontal angles and flat steps, horizontal acceleration/friction, command expiration, jumping, crouching, and hit-ground/leave-ground, damaging-impact and dry-to-fluid entry events and gap detection (bits 1 through 64). Initial Z is raised by 0.25 units. Native prediction retains frame displacement and converts to velocity around friction and acceleration. Gravity subtraction uses the observed double-literal 0.1 factor before those conversions. The vector normalizer returns squared length times its rounded inverse root; jump displacement includes the observed five-unit term. Event time/frame indices follow the native zero-based stopping frame. These details were derived from varied inputs to unchanged reference code, not from implementation translation.

## Tilted step landings

A step probe with a positive unit normal uses the same strict acceptance threshold as a flat landing: normal Z must exceed `phys_maxsteepness`. Equality and smaller values reject the step and retain the original wall for sliding. A start-solid step is rejected before its plane is queried. Acceptance retains the original wall-contact XY, adopts only the probe endpoint Z, zeros vertical velocity, and continues the horizontal displacement computed from the inset origin. It does not project movement onto the landing slope or independently charge an impact-damage event. The ordinary later ground/liquid/gap checks retain their existing ordering and trace-output rules. ## Fluid-entry area metadata

When internal vertical frame displacement is at most ten, the predictor first samples BSP point contents 22 units below the current position, then looks up the current AAS area and its contents flags. BSP water/slime/lava bits and AAS water 1, lava 2 and slime 4 independently contribute to the requested entry-event mask. The reported `endContents` retains only the BSP sample; AAS water with a dry BSP sample can therefore return water event 4 with zero contents. The entry result reuses the sampled area. This check runs even when no fluid stop is requested, and skips both sources above the strict vertical threshold. Initial swimming and the gap-water test retain their separate BSP-only queries.

## Presence-hull transitions

An active grounded command with Z strictly below −300 selects the crouch hull and crouch speed limit without querying standing clearance. Otherwise a currently crouched hull queries available presence at the frame's starting position: standing bit 2 restores the standing hull, while its absence retains the current hull. A standing hull does not perform this query or automatically crouch. Collision determines whether it fits; an impossible fit can return the ordinary bounded failure. Command expiration also ends the crouch speed limit, even when low clearance retains the crouch hull. This retained hull uses the normal walk speed limit for subsequent acceleration.

Six authored tests cover retained crouch speed, strict command thresholds and lookup short circuiting, recovery across a spatial clearance boundary, command expiry, blocked standing hulls and final-contact event/budget ordering. A production comparison against unchanged native prediction covers 20,000 controlled floor/open-air scenarios: 10,000 default settings, 5,000 with zero crouch maximum speed and 5,000 with walk maximum speed 1000. All reported movement float bits, presence/events, trace flags and counts match. Hashes of the complete presence-trace, clearance and contents query arguments and order also match. Inputs vary initial hull, ground state, changing presence bits, command duration, jump/crouch thresholds, momentum, frame durations and event masks. ## Gap event

Gap event bit 64 is evaluated only while ungrounded, after liquid-entry and requested ground/leave-ground events. The extra AAS trace uses crouch presence 4 and pass entity −1, excluding all dynamic entity collision. It descends by `float(phys_maxbarrier + 48)` from the current position; `phys_maxbarrier` defaults to 33 and is independent of `sv_maxbarrier`. Settings preserve the former ten-argument constructor with that default, and retain the existing finite 0..100000 bound.

The native endpoint threshold is `hitZ < float(float(currentZ - phys_maxstep) - 1)`. Rewriting it as a difference of heights changes results at float boundaries. A start-solid trace or failed strict threshold suppresses the subsequent contents query. Otherwise water bit 32 at the **requested bottom**, rather than the actual hit endpoint, suppresses the gap. Slime/lava bits alone do not suppress it, and the gap trace fraction does not decide the event. A gap restores the current frame's starting position, including the initial 0.25-unit adjustment; it reports that position's area, the post-movement velocity, zero contents, the zero-based frame/time and the ordinary main movement trace.

Six authored tests cover event precedence, frame rollback, strict thresholds and float cancellation, forced static tracing, requested-bottom water, start-solid short circuiting, independent settings and trace identity. The initial 10,000 controlled native decisions are supplemented by 24,000 endpoint-threshold probes, including noninteger step settings that distinguish the subtraction order. A 9,000-request comparison of the production predictor against unchanged native prediction covers nine step/barrier configurations, varied frame durations, rising/falling movement, crouching, command expiry, stop masks and supplied gap traces/contents. Every output float bit, discrete field, complete trace record and presence-trace/contents query count matches. These are controlled collision callbacks; downward-facing/non-unit step planes remain explicit guards. The subsequent swimming extension preserves the gap checks and their precedence. The separate [jump run-start service](BOTLIB_JUMP_RUN_START.md) uses this gap event in its prediction mask.

## Swimming prediction

Each frame samples the existing BSP-only swimming predicate at its starting position, two units below the origin. Water, slime and lava all select the swimming branch. This predictor uses that binary sample, not the game's multi-level water-depth calculation. Entering or leaving a spatial liquid volume changes the branch on the next frame; AAS area fluid flags still contribute separately to the existing entry stop events.

The measured settings are `phys_waterfriction=1`, `phys_watergravity=400`, `phys_maxswimvelocity=150` and `phys_swimaccelerate=4`. They are independent of dry settings and use the existing finite 0..100000 limit. The previous ten- and eleven-argument `Settings` constructors retain these defaults, while `Settings.from` reads overrides already passed by the host.

Swimming applies friction to horizontal speed whether grounded or airborne. It retains vertical momentum during friction, shares `phys_stopspeed`, and uses the established control-speed × frame-time × friction ordering. Water gravity uses the same observed 0.1 factor and frame-displacement representation as dry gravity. Command normalization, speed limiting and acceleration use all three axes. A grounded downward command still selects crouch presence, but its acceleration uses the swim speed cap. An upward command accelerates in water without adding the dry jump impulse or starting its step-suppression interval. Command expiration stops acceleration while water friction and gravity continue.

Contacts use the established bounded clipping and step process. A frame that began swimming suppresses the damaging-impact stop event, while ordinary ground/leave-ground, fluid and gap checks retain their existing ordering. The cached swimming state is used for the whole frame, including a contact that exits the liquid. Normal completion and fluid stops continue to clear the nested trace; other supported stops retain their measured trace records.

Seven new authored tests cover horizontal-only friction, stop-speed behavior, vertical/diagonal commands, ground/crouch distinctions, exiting liquid, impact-event suppression, combined fluid stops and independent bounded settings. Together with the existing predictor/world/directional/run-start tests, all 53 focused tests pass. The prior 60,000 directional mask cases, 30,000 combined ceiling/floor cases, 50,000 positive-incline cases and 1,400 fluid-entry cases were rerun after this change with no new differences or exclusions. The directional observer's rounded printed values differ by at most 0.0001; the ceiling and incline comparisons match exact floats.

## Target-box trajectory operation

`predictHitBox(request, absoluteMinimum, absoluteMaximum)` supplies the separate target-box
operation used by [suspended jump-pad item localization](BOTLIB_JUMP_PAD_ITEMS.md). It requires
ordinary stop mask zero, reports bounding-box event 2048 only through this overload, and keeps
the ordinary `predict(request)` / trap 318 supported-mask contract unchanged. A hit uses the
actual main world-trace segment and precedes fluid/ground queries. A miss in this mode bypasses
ordinary contact sliding and proceeds to the next frame's measured physics. The linked document
records exact face/edge/initial-overlap semantics and the 50000 full-record native comparisons.

## Dynamic AAS world and prediction ABI

`AasMovementWorld(navigation, entityTrace, pointContents)` implements the predictor's `World`. Static collision uses `AasPresenceTrace` over the already expanded AAS partition. An optional per-area callback clips each permitted leaf segment against that area's linked engine entities. `EntityWorld.traceEntity(number,request)` supplies only the selected entity's current collision shape; static server BSP collision and server owner filtering do not replace this AAS composition.

`link(number,absoluteMins,absoluteMaxs)` expands links by the standing presence hull. Every update relinks at the front, including unchanged bounds; equal collision fractions therefore retain the most recently linked entity. Negative pass-entity values disable all dynamic collision. Nonnegative values skip that entity and trace all other linked candidates with mask 65537 (`SOLID | PLAYERCLIP`) and runtime standing/crouch bounds. Candidate selection uses the callback fraction, even for start-solid results. A selected start-solid result reports global fraction zero while retaining the callback endpoint. Other dynamic fractions are measured from the original ray start to that endpoint. Dynamic hits retain the preceding area and return zero blocked-area/plane fields; the static 0.125-unit final position backoff does not apply to them.

The first missed update invalidates entity information while preserving its links; a second missed update removes those links. Explicit null updates unlink while retaining their last metadata. The host applies the measured origin/bounds/angle and first-frame relink rules described in [entity lifetime](BOTLIB_ENTITY_LIFETIME.md). Bounding-box solids copy supplied bounds; nonsolid/trigger updates retain prior bounds, initially zero. Brush solids use their BSP model bounds. Any nonzero float angle, including 360 degrees, replaces bounds with a centered sphere's enclosing cube: its radius is the float square root of the left-associated sum of squared per-axis maximum absolute bounds. The engine callback's model origin is zero. This policy was observed through the actual unchanged engine import callback, not inferred from rotation geometry.

The world caps linkage at two million entity-area pairs, entity IDs at 1024 and candidate collision calls at one million per trace. Seven authored tests cover segment clipping, runtime hulls/masks, equal-hit ordering, explicit removal, negative/pass-entity filtering, start-solid selection, invalid bounds and independent area/BSP contents. A 20,000-query differential audit across ten original maps includes 4,967 dynamic hits: every discrete field matches the unchanged reference and the maximum numeric difference is 0.00001. The callback uses controlled fractions/start-solid results to isolate linkage and composition from collision-shape arithmetic. A separate 10,000-case model-bounds audit matches all nine returned float bit patterns, including asymmetric bounds, signed zero, subnormal angles and full rotations. Server tests cover direct current-shape tracing without owner filtering, retained bounds and link lifetime.

Trap 318 validates the complete 84-byte `aas_clientmove_t` output before prediction. Its offsets are end position 0, end area 12, velocity 16, 36-byte trace 28, presence 64, stop event 68, contents 72, time 76 and frames 80. The nested trace uses start-solid 0, fraction 4, end position 8, entity 20, preceding area 24, blocked area 28 and plane 32. Normal completion and fluid-entry events clear the trace bytes; ground, damaging-impact and gap events write the main movement trace. The host commits only a successful prediction, leaving the entire output unchanged on failure or unsupported input. Guest tests exercise sentinel bytes and both explicit game ABI profiles. The original retail call's thirteen arguments and result allocation were observed directly, with the public compatible header establishing the complete record declaration; this does not claim every retail output field was independently read by the original guest during that probe. Debug visualization and unverified prediction domains still fail explicitly.

The callback and record contracts refer to the [public AAS declarations](https://github.com/ioquake/ioq3/blob/main/code/botlib/be_aas.h) and [prediction declarations](https://github.com/ioquake/ioq3/blob/main/code/botlib/be_aas_move.h). Authored observers and unchanged reference objects remain ignored development artifacts. No native engine code, original media or reference harness is bundled with the mod.
